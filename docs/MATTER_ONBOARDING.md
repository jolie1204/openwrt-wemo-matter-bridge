# Matter Onboarding

Release builds do not ship with one shared fixed setup passcode.

On first boot or first service start, the OpenWrt package generates unique
onboarding data and stores it here:

```text
/etc/wemo-matter-bridge/matter-onboarding.json
```

The file contains:

```json
{
  "setup_passcode": 12345678,
  "discriminator": 1234,
  "qr_payload": "MT:...",
  "manual_pairing_code": "...",
  "generated_at": "2026-05-22T00:00:00Z"
}
```

The same passcode and discriminator are also written to the Matter factory
configuration file used by the bridge service:

```text
/data/wemo-matter/chip/chip_factory.ini
```

The service also starts `wemo-bridge-app` with `--passcode` and
`--discriminator` so the generated values are explicit at runtime.

## Show the QR Code Again

```sh
wemo-matter-bridge qr
```

This prints:

- Matter QR payload string
- manual pairing code
- ASCII QR code when `qrencode` is installed
- PNG file at `/tmp/wemo-matter-bridge-qr.png`
- PNG file at `/www/wemo-matter-bridge-qr.png` when `/www` exists and is writable

## Reset Onboarding

```sh
wemo-matter-bridge reset-onboarding
```

This deletes local onboarding data and generates new values. Already
commissioned Apple Home or Google Home controllers may need the bridge removed
and added again.

For noninteractive reset:

```sh
wemo-matter-bridge reset-onboarding --force
```

## Development Mode

The package has explicit config switches:

```sh
uci set wemo-matter-bridge.main.generate_onboarding='1'
uci set wemo-matter-bridge.main.dev_fixed_onboarding='0'
uci commit wemo-matter-bridge
```

Release default:

```text
generate_onboarding=1
dev_fixed_onboarding=0
```

Development-only fixed onboarding:

```sh
uci set wemo-matter-bridge.main.dev_fixed_onboarding='1'
uci commit wemo-matter-bridge
wemo-matter-bridge reset-onboarding --force
```

Development mode uses the common Matter example passcode. It is unsafe for real
users because every image would share the same onboarding secret.

Environment overrides are also supported for automated testing:

```sh
WEMO_BRIDGE_GENERATE_ONBOARDING=ON
WEMO_BRIDGE_DEV_FIXED_ONBOARDING=OFF
```

## Notes

The QR payload and manual pairing code are generated by the Matter SDK payload
generator compiled into `wemo-bridge-app`; the shell wrapper does not implement
its own Matter QR encoding.

This project is not represented here as an official Matter certified product.
